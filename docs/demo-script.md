# Демонстрация за три минуты

**0:00 — задача.** «Руководитель просит проанализировать продажи за последние 30 дней. PULSE показывает показатели, проблемные сделки и следующие действия в одном отчёте». Сразу укажите, что данные вымышлены, а демо-анализ выполняется локальными правилами.

**0:20 — обзор.** Откройте 30 дней, покажите созданные и успешно закрытые сделки, суммы и текущую воронку. Переключите на 7 дней: показатели периода меняются по исходным событиям. Объясните, что воронка и проблемы задач отражают текущий срез и поэтому могут оставаться прежними.

**0:50 — проблемная сделка.** Выберите фильтр «Без задач» или «Просроченные». Откройте сделку и покажите ответственного, бюджет, задачи и рекомендацию. Отсутствие следующего действия определяется незавершёнными задачами самой сделки; задачи контакта не относятся автоматически ко всем его сделкам.

**1:20 — звонок с подтверждением.** Откройте связанный разговор: содержание, следующий шаг и фрагмент расшифровки с временной отметкой. «Рекомендация проверяема: руководитель видит, из какого фрагмента она появилась». Уточните, что в демо есть синтетический текст, а реальные записи получают от выбранной телефонии.

**1:50 — действие человека.** Покажите рекомендации и экспорт. «Система помогает определить, что проверить первым. Назначение задач, контакты с клиентом и оценку сотрудника утверждает руководитель». Выгрузка демонстрирует переносимость результата, а не запись в CRM.

**2:10 — техническая часть.** Откройте [архитектуру](architecture.md) и [скрипт amoCRM](../examples/amocrm_problem_deals.py). Объясните пагинацию, фильтр незавершённых задач, исключение закрытых сделок и сохранение данных в SQLite. Для демонстрации скрипта без настоящих ключей достаточно кода и автотестов коннектора; вымышленный ответ API не следует выдавать за подключение.

**2:40 — результат и развитие.** «Получился запускаемый прототип с проверяемыми расчётами и адаптерами для внешних данных. Следующий этап — проверить полноту выгрузки и качество анализа на разрешённых данных реального аккаунта». Подчеркните, что бизнес-эффект пока не измерялся.

## Вопросы, которые могут задать

| Вопрос | Короткий ответ |
| --- | --- |
| Где здесь AI? | В анализе расшифровок: договорённости, возражения, следующий шаг. Демо использует правила; команда `analyze-calls` явно подключает LLM. |
| Почему сумму сделок нельзя назвать выручкой? | CRM хранит бюджет сделки. Для денежных поступлений нужен источник платежей. |
| Почему старые сделки попадают в отчёт за 30 дней? | Период относится к событиям создания, закрытия и звонков; проблемы открытого портфеля считаются на текущий момент. |
| Можно ли восстановить воронку на каждый день? | Для этого нужен журнал переходов. Один текущий статус сделки не даёт историю. |
| Есть ли реальные записи? | В демонстрации — синтетические расшифровки. Для собственных записей есть явная команда распознавания; импорт телефонии требует её адаптера. |
| Может ли система ошибиться в обещании? | Да. Поэтому вывод содержит подтверждение и поступает человеку на проверку. |
| Какой эффект для бизнеса? | Пока подтверждён технический результат; влияние на продажи и затраты времени не измерялось. |
