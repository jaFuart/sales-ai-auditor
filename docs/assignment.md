# Ответы на задание

Этот материал описывает реализованный демо-проект PULSE. Его можно использовать для технических пунктов задания; личные ответы в пунктах 5–6 нужно заполнить собственными фактами.

## 1. Архитектура решения

Три роли: координатор, аналитик звонков и составитель отчёта. Координатор читает amoCRM через REST API v4 и получает данные телефонии через адаптер провайдера. Записи проходят распознавание речи; аналитик извлекает договорённости и возражения с подтверждениями. Python рассчитывает показатели и проблемы задач. Составитель объединяет всё в отчёт. Нормализованные данные и анализ хранятся в SQLite, аудио — отдельно. Подробная схема помещается на одной странице: [architecture.md](architecture.md).

В демо доступны синтетические данные, рабочий amoCRM-коннектор, импорт расшифровок и опциональные команды ASR/LLM. Получение записей от конкретной телефонии требует её адаптера. Без ключей отчёт формируется локальными правилами.

## 2. Автоматизация, человек и три главных риска

Система сама собирает и нормализует данные, считает показатели, находит открытые сделки без незавершённых задач и с просрочками, выделяет договорённости в звонках и формирует рекомендации с источниками.

Руководитель проверяет спорные фрагменты, уточняет причины проблем и утверждает следующие действия. Оценка сотрудников, изменение CRM и контакты с клиентами не выполняются автоматически.

1. **Неполные или неправильно связанные данные.** Права доступа, пропущенные записи, задачи контакта и несколько сделок одного клиента влияют на полноту анализа. Нужно проверять покрытие источников и уверенность сопоставления; отсутствие данных не означает отсутствие работы.
2. **Ошибки распознавания и интерпретации.** Шум, неоднозначные обещания и ошибки LLM могут породить неверную рекомендацию. Нужны подтверждающие цитаты, временные отметки, проверка структуры ответа и участие руководителя в спорных случаях.
3. **Доступ к коммерческим и персональным данным.** Записи и токены требуют ограниченного доступа, подходящего хранения и согласованных условий обработки у AI-провайдера. Реальные данные нельзя включать в публичный демонстрационный сайт.

## 3. Фрагмент интеграции до 50 строк

[examples/amocrm_problem_deals.py](../examples/amocrm_problem_deals.py) получает все страницы сделок и незавершённых задач, исключает закрытые статусы 142/143 и выдаёт проблемные сделки. Для просрочек время фиксируется перед загрузкой. «Без задач» означает отсутствие незавершённых задач, привязанных непосредственно к сделке; отбор охватывает все открытые сделки, а не только созданные за 30 дней.

Запуск с `AMO_SUBDOMAIN` и `AMO_ACCESS_TOKEN`:

```bash
python3 examples/amocrm_problem_deals.py
```

Ошибки HTTP и некорректные ответы прерывают выполнение. Для более полного коннектора с обработкой временных ошибок используется `auditor` и команда `sync-amo`. Поведение пагинации и фильтра задач сверено с [документацией задач amoCRM](https://www.amocrm.ru/developers/content/crm_platform/tasks-api), закрытые статусы — с [документацией воронок](https://www.amocrm.ru/developers/content/crm_platform/leads_pipelines).

## 4. Реальный AI-проект

**Проект:** [PULSE — AI-аудитор продаж](https://github.com/jaFuart/sales-ai-auditor).

**Задача:** объединить показатели продаж и содержание звонков в проверяемый отчёт, чтобы руководитель мог быстро найти сделки, требующие следующего действия.

**Стек:** Python со стандартной библиотекой, amoCRM REST API v4, SQLite, HTML/CSS/JavaScript, опциональные ASR и LLM через OpenAI API, GitHub Actions и Docker.

**Результат:** работающий демо-интерфейс, воспроизводимые отчёты за 7/14/30 дней, загрузка сделок и задач, импорт расшифровок, анализ звонков с подтверждениями и экспорт данных. Автотесты проверяют ключевую бизнес-логику и интеграционные границы. В демо использованы синтетические данные и правила; внешняя AI-обработка запускается только явно с ключом.

Это новый портфолио-проект, а не внедрение у клиента. Изменение выручки, времени работы руководителя и качества продаж не измерялось. Проверка внешних коннекторов на действительных данных зависит от предоставленных доступов.

## 5. Чему я научился самостоятельно за последние полгода

Здесь нужен личный ответ автора. Новый проект подтверждает применение технологий, но не доказывает, когда они были освоены.

Для подготовки ответа выберите один реальный навык и укажите:

- Что было новым и почему вы решили это изучить.
- Как учились: документация, эксперименты, курс, свой проект.
- Где применили и какой конкретный результат можно показать.

Удобная структура: «За последние полгода я самостоятельно освоил **[навык]**. Изучал его через **[источники и практику]**. Применил в **[проект]**, где сделал **[конкретная работа]**. Результат подтверждается **[артефакт или измерение]**».
